## 当前配置与成果

| 项目 | 实际情况 |
|---|---|
| 开发板 / 器件 | MES50HP / PGL50H，FBG484，-6 |
| 时钟 | 板载 50 MHz 经 PLL 得到 CPU 80 MHz |
| 结果串口 | 名义 460800，当前通常为 COM7 |
| 监听总线 | 最高已验证名义 921600；当前按 8N1 收发 |
| 设备端 / 控制器 | 电脑两个 USB-RS485 端口，通常 COM8 / COM9 |
| 多地址 | 同一条总线模拟 1～8 地址，并非 8 路独立物理通道 |
| 读取量 | FC03，每次 1～125 个 16 位寄存器 |
| 间隔 | 额外 interval 可为 0，高速每方向仍保留至少 1.75 ms 静默 |
| 回应门限 | 默认 100 ms；可查询或手动修改 |
| 存储 | 指令和数据各 64 KiB 片上存储器，不使用 DDR3 |
| 时序 | 80 MHz 约束满足，报告估算 Fmax 83.382 MHz，最差建立裕量 0.507 ns |

## 相对原有应用，哪些是后来改进的

原仓库后续版本已经具有中断驱动、事件缓冲、多地址统计、超时、自动波特率、故障日志及 GPIO 告警。本轮在此基础上做了真实板级部署和以下改动：

- **自动重锁修复：** 为未结束短帧提供有界收尾，收到第一帧合法证据后最多等 2 秒确认第二帧；重锁保留手动超时门限。原先 19200 回到 9600 的一轮 75 秒仍未锁定，修复后普通轮询测得 1.611 秒。
- **高速接入：** 增加 230400/460800/921600 候选及高速最小观察时间；保留两帧 CRC 有效的确认条件。
- **正常输出限量：** 原先逐项输出全部数值，改成前 4 项预览；新增 `report compact`，省略数值预览但仍处理完整报文。
- **分段输出：** 整行进入 1024 字节发送队列，每轮最多尝试发送 16 字符；串口满时返回接收处理；`dev`、`log` 取快照后逐行生成，显示丢行有明确计数。
- **实时摘要：** 新增 `summary`、`summary reset`，基于板端处理字节和周期计数增量计算吞吐、帧率和有效问答等。
- **坏帧线索：** CRC 错误输出帧头地址、功能码和长度，帧头身份明确标为未校验，不给错误设备身份背书。
- **结果口升级：** UART 分频 694→174，结果串口 115200→460800；CPU 和监听采样不变。
- **统一桌面工具：** Python/Tkinter 实现并打包 EXE，集中控制两端发生器、读取结果口、展示原文及事件归并、保存记录。
- **随机情况：** 在正常、坏 CRC、延迟、无回应、离线/恢复之外加入截断、异常应答、地址错误，记录伪随机种子并穿插连续正常窗口。

## 板端计算与电脑展示的边界

板端 CPU 执行 CRC、协议处理、请求/回应配对、响应计时、超时、离线/恢复及统计。电脑负责产生测试流量、读串口和整理展示。

当前中文“迟到回应”“回应地址不匹配”含电脑对板端原始 REQ/TIMEOUT/RSP 的关联步骤；颜色、折叠和观察文字也在电脑处理。它们不读取模拟器故障标签直接生成结论，但不能表述为所有分析全由 CPU 完成。若比赛要求全部分析下沉到板端，这两项仍需单独处理。
