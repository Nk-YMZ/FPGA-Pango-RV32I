# 总线监听演示台

一个窗口整合两个电脑RS485端口、开发板结果串口和实时统计。继续使用已经下载的80MHz工程，无须重编译或重新下载。

## 打开与启动

1. 关闭PuTTY及以前的控制器、设备模拟脚本，释放三个串口。
2. 双击“总线监听演示台.exe”。桌面副本和同目录启动cmd均可使用。
3. 窗口自动连接开发板；点击“开始通信”。
4. 初始只有一块“终端”。点标题旁的无框双线箭头，按2∶1∶1横向展开“终端 / 开发板输出 / 控制器记录”；再点收回。开发板中的异常原文标红，控制器记录保持黑字。
5. 点击“停止通信”停止电脑两端。开发板仍然连接、继续监听；关窗口释放全部端口。

## 默认配置

点“设置参数”展开，直接点击参数值选择，没有常驻输入框或附加标识。读取数量、地址和间隔也可选“自定义”。开发板的连接/断开按钮在这里。停止通信后才能修改发生器参数；修改开发板串口后要断开并重新连接开发板。

| 参数 | 默认值 |
|---|---|
| 开发板结果串口 | COM7，固定115200 |
| 电脑控制器 | COM9 |
| 电脑模拟设备 | COM8 |
| 总线波特率 | 921600 |
| 每次读几个值 | 125 |
| 地址 | 1,2,3,4,5,6,7,8 |
| 额外间隔 | 0秒 |

波特率是两只RS485适配器的设置，不是开发板结果串口的设置。必要静默仍保留，额外间隔0不等于无线间隔。

## 演示故障

点“开始通信”右侧箭头，在按钮右侧竖排显示设备状态选项；选中后自动收起。重复选择当前状态也会收起；点击其他区域或按Esc同样收起。选项对当前全部地址生效。

| 选择 | 电脑端行为 | 主要看开发板输出 |
|---|---|---|
| 正常回复 | 按请求回复完整数据 | REQ/RSP、有效问答持续增加 |
| 校验错误 | 故意损坏回复的校验字节 | 校验错误、超时；不会当作有效回复 |
| 延迟200ms | 收到请求后等200ms回复 | 原有超时阈值小于200ms时出现TIMEOUT |
| 无回应 | 收到请求但保持静默 | TIMEOUT，连续发生后可能报设备离线 |
| 每台回应3次后离线 | 每个地址先正常回复3次，再保持静默 | 先正常，再超时、离线 |
| 随机情况 | 随机穿插正常、错校验、延迟、无回应；部分地址先回应3次、无回应3次再恢复 | 对照板端CRC、超时、离线和恢复；控制器记录注明“电脑注入” |

切回“正常回复”恢复通信；如果固件因连续坏帧开始扫描，等它重新锁定后看有效问答恢复。“解除告警”发送alarm off；它不消除仍在发生的故障。

切换不同状态时，本地终端归并和两侧显示重新开始，控制器计数也从0开始；开发板统计观察窗口重新计时。正常选项为浅灰底，选中的故障为浅红底。完整原始文件继续保存，固件累计设备统计、事件日志和锁存告警不会因此清除。

随机情况按请求安排正常与故障，并在约5～8秒的混合阶段后穿插约3秒连续正常通信。阶段离线按设备推进；进入连续正常时段时恢复正常回应。日志保存随机种子和每笔实际注入情况，复核以实际记录为准；这些设置不参与板端诊断或界面结论判断。

## 开发板命令

在占位提示“log … / dev / stat”的命令栏输入命令，按回车或点击红色“发送”。提示文字不会作为命令发送。常用查询、解除告警、重新计时和显示选项在“更多”内。自动统计查询和手动命令按顺序发送。

| 输入或按钮 | 显示 |
|---|---|
| `stat`／总计 | 自清零以来的帧、请求、回复、错误等累计值 |
| `dev`／设备 | 已识别设备及各自的统计 |
| `log`／事件 | 固件保存的故障事件 |
| `alarm off`／解除告警 | `OK alarm=0` |
| `clear` | 清除固件支持清除的统计；累计显示丢行等仍按原固件规则处理 |
| `bitdiv` | 当前锁定的接收位周期 |
| `help` | 固件支持的命令 |

“更多→重新计时”只重置实时统计的观察窗口，不清设备、事件和告警。命令回复显示在终端。

## 错误归并

终端中的实时错误按“类型 → 设备 → 逐条原文”展开，每条带接收时间。×26代表26条报告，展开后有26条；同类重复内容先折叠显示计数。

- 计数是本次场景收到的报告条数，不是独立故障次数；“更多→清空本次归并”只清本地归并，不清固件日志。
- 每种错误、每台设备最多保留最近2000条可展开记录，超过时明确注明“最近2000条”，更早原文仍可在完整记录中查看。
- 总览的“近1.0秒：请求超时4次”来自开发板两次摘要间的增量；终端“本场景累计×22”是本场景接收到的报告条数，时间范围不同。
- “超时后同址回应”是电脑对板端原文的归并：看到请求、超时后，在新同址请求之前又看到数量一致的同址有效回应。展开后同时保留TIMEOUT和RSP依据。它不重新计算硬件响应时间，也不把此前超时减掉。
- TIMEOUT等有地址的报告归到对应设备；未给地址的CRC错误标为“未归属”，不猜测设备。
- 反复执行log只显示历史查询回复，不会重复累加实时归并计数。
- “开发板输出”保留未经归并的完整原文，所有原始记录仍保存到文件。

## 看数与保存

- 数据：板上CPU每秒处理的字节，按1000字节折合1KB。
- 有效问答：板上判定成功配对的请求和回复，不是电脑预设值。
- “当前窗口未见异常”表示最新板上统计未报告校验/格式错误、超时或采集丢失；没有流量时显示“等待总线数据”，统计过期时不继续显示正常结论。它不代表已测出CPU极限，也不代表已清除锁存的硬件告警。
- 有异常时，结论下方直接给出错误率、未响应次数或采集丢失数量。完整字段仍可从“更多→显示统计原文”查看；显示丢行原始值是自启动累计，结论使用新增量。
- 控制器记录显示电脑发出的请求、收到的回复或等待超时，保留这一端即可独立对照板上分析；不再重复显示模拟设备端。故障模式中的错帧、无回复是故意制造的。
- 停止发生后数字变0正常。手动查询较长回复时，统计更新时间可能稍延后。
- 在“更多”中取消“跟随最新”可翻看输出；“显示统计原文”可在终端显示SUM。展开三栏后，开发板输出包含正常REQ/RSP；电脑端长报文仅预览前24字节，完整报文保存在文件中。
- 点“更多→打开完整记录”进入日志目录：board内保存完整开发板输出和统计；bus内保存两个发生端口的完整报文及本次结果。
- 当前观察和标题旁方形灯：有正常数据流量时为绿色，无流量或等待时为浅灰色，有异常时为红色；开发板异常行和开发板标题随异常标红，控制器原文保持黑字。终端的OK及恢复信息用绿色。颜色不修改保存的原文。

实际分析仍由FPGA里的CPU完成，真实数据仍经过两只适配器和RS485线路。这个工具只是统一控制与展示。

## 如何核对判断来自哪里

| 显示内容 | 来源 |
|---|---|
| CRC/格式错误、TIMEOUT、离线/恢复、SUM计数 | 开发板固件输出 |
| 迟到回应、错误折叠、当前观察文字与颜色 | 电脑依据板端原文归并，不读取模拟器模式作为判断依据 |
| 控制器记录里的“电脑注入” | 电脑发生器的预期行为，只作对照 |

可做一次独立串口核对：先开始通信，再到“设置参数”点击“断开开发板”，电脑两端继续运行。用PuTTY打开COM7，460800、8N1、无流控，直接看开发板的REQ/RSP、TIMEOUT、FRAME和DIAG原文。此时演示台已经读不到COM7，PuTTY中的诊断仍然存在。完成后关闭PuTTY，回演示台连接开发板。不要关闭整个演示台，否则内置发生器也会停止。

截图证据建议同时保留：控制器注入记录、开发板原文、终端展开的对应记录。上方摘要增量与下方累计不要当作同一计数比较。

## 本轮更新：中文终端与精简回应

- 终端的常见故障、设备记录、查询回复改为中文。右侧“开发板输出”和完整日志保留板端原文，归并依据不变。
- 高速档每段静默改为1.75ms，额外间隔仍为0；低速档自动保留更长的3.5字符间隔。
- 更多→精简回应输出，等同发送`report compact`：每帧保留地址、数量和响应时间，省略正常回应中的数值预览。数据仍按125个值完整接收、校验、解析。
- 更多→恢复数据预览，等同发送`report full`。上电默认原格式，本次已将板上运行状态切为精简格式。
- CRC错误现在提供“帧头地址XX（未校验）”，用于定位线索；地址本身可能损坏，不作为确认设备、不计入有效设备画像。
- 连续应用上电默认回应时限100ms，自动重锁后保留；需要调整时仍用timeout命令，参数单位为80MHz时钟周期。
- 每次读取保持125，这是当前FC03协议上限。

## 随机情况新增内容

入口仍为“随机情况”，不增加独立选项。内部加入：截断到帧头的短报文、异常码02的有效异常应答、重新计算CRC但改用另一地址的回应。板端分别提供格式错误、EXR异常应答，以及REQ/RSP地址等原文；界面按原文归并，不读取注入标签来生成判断。截断是本次注入动作，现场单靠格式错误不能唯一确定发生原因。

终端示例缩短为“校验失败（帧头01未校验，255字节）”“设备03超时（100ms）”“地址不符：请求03，回应04”。错误归类与原始日志不变。异常应答是校验正确的设备业务拒绝，不等于CRC错误。

随机方式为受约束伪随机：每次启动从系统随机源产生种子，类型分组洗牌，并穿插约3秒连续正常时段。不是固定顺序，也不是各帧独立等概率。日志保存种子、时间及实际动作；复核以实际发送记录为准。
